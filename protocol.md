# AI-augmented IDE Protocol (AIDEP) Specification - Draft 0.1

## Overview

AIDEP defines a protocol for communication between development tools (IDEs, editors) and AI augmentation servers. The protocol enables human-driven, AI-augmented development where developers remain in control of the development flow while leveraging AI capabilities for specific, well-defined tasks.

Unlike autonomous AI agents, AIDEP servers respond to explicit developer requests and return results that the client decides how to apply.

## Base Protocol

AIDEP uses [JSON-RPC 2.0](https://www.jsonrpc.org/specification) over WebSocket. The WebSocket transport enables:
- Bidirectional communication
- Server-initiated streaming for long-running generations
- Future extensibility for client-to-server signals (cancel, refine)

### Message Types

**Request**: Client → Server, expects response
**Response**: Server → Client, result of request  
**Notification**: Either direction, no response expected
**Stream**: Server → Client, partial results for streaming responses

## Basic Structures

### Position

A position in a text document, expressed as zero-based line and character offset.

```typescript
interface Position {
  /**
   * Line position (zero-based).
   */
  line: uinteger;

  /**
   * Character offset on the line (zero-based).
   */
  character: uinteger;
}
```

### Range

A range in a text document.

```typescript
interface Range {
  /**
   * The range's start position (inclusive).
   */
  start: Position;

  /**
   * The range's end position (exclusive).
   */
  end: Position;
}
```

### TextDocumentIdentifier

Identifies a text document.

```typescript
interface TextDocumentIdentifier {
  /**
   * The text document's URI.
   */
  uri: DocumentUri;
}
```

### TextDocumentPosition

A position in a specific text document.

```typescript
interface TextDocumentPosition {
  /**
   * The text document.
   */
  textDocument: TextDocumentIdentifier;

  /**
   * The position inside the text document.
   */
  position: Position;
}
```

### GeneratedContent

Content generated by the server.

```typescript
interface GeneratedContent {
  /**
   * The generated text content.
   */
  text: string;

  /**
   * Optional language identifier for syntax highlighting.
   */
  languageId?: string;
}
```

## Lifecycle

### Initialize Request

The `aide/initialize` request is sent as the first request from the client to the server.

_Request_:
- method: `aide/initialize`
- params: `InitializeParams`

```typescript
interface InitializeParams {
  /**
   * The root URI of the project/workspace.
   */
  projectRoot: DocumentUri;

  /**
   * Information about the client.
   */
  clientInfo?: {
    name: string;
    version?: string;
  };

  /**
   * Capabilities provided by the client.
   */
  capabilities?: ClientCapabilities;
}

interface ClientCapabilities {
  /**
   * Whether the client supports streaming responses.
   */
  streaming?: boolean;

  /**
   * Whether the client supports cancellation.
   */
  cancellation?: boolean;
}
```

_Response_:
- result: `InitializeResult`

```typescript
interface InitializeResult {
  /**
   * Unique identifier for this session.
   */
  sessionId: string;

  /**
   * Information about the server.
   */
  serverInfo?: {
    name: string;
    version?: string;
  };

  /**
   * Capabilities provided by the server.
   */
  capabilities: ServerCapabilities;
}

interface ServerCapabilities {
  /**
   * The server supports `aide/implementFunction`.
   */
  implementFunction?: boolean;

  // Future capabilities...
  // explain?: boolean;
  // refactor?: boolean;
  // review?: boolean;
}
```

### Initialized Notification

Sent from client to server after receiving `InitializeResult`.

_Notification_:
- method: `aide/initialized`
- params: `{}`

### Shutdown Request

Sent from client to server to end the session.

_Request_:
- method: `aide/shutdown`
- params: `{}`

_Response_:
- result: `null`

## Augmentation Capabilities

### Implement Function

The `aide/implementFunction` request asks the server to generate the implementation of a function.

The server generates code but does **not** modify files. The client receives the generated content and decides whether/how to insert it.

_Request_:
- method: `aide/implementFunction`
- params: `ImplementFunctionParams`

```typescript
interface ImplementFunctionParams {
  /**
   * Location where the function should be implemented.
   */
  location: TextDocumentPosition;

  /**
   * Description of what the function should do.
   */
  prompt: string;

  /**
   * Optional function signature if already defined.
   */
  signature?: string;

  /**
   * Optional token for streaming progress.
   */
  partialResultToken?: ProgressToken;
}
```

_Response_:
- result: `ImplementFunctionResult`

```typescript
interface ImplementFunctionResult {
  /**
   * The generated function implementation.
   */
  content: GeneratedContent;
}
```

_Partial Result_ (if streaming):

For streaming responses, the server sends `$/progress` notifications:

```typescript
interface ImplementFunctionPartialResult {
  /**
   * Chunk of generated content.
   */
  chunk: string;
}
```

_Stream Completion_:

The final `$/progress` notification includes:

```typescript
interface ImplementFunctionStreamEnd {
  /**
   * Signals end of stream.
   */
  done: true;

  /**
   * Complete generated content (optional, for clients that missed chunks).
   */
  content?: GeneratedContent;
}
```

## Progress and Streaming

### Progress Token

```typescript
type ProgressToken = string | integer;
```

### Progress Notification

_Notification_:
- method: `$/progress`
- params: `ProgressParams<T>`

```typescript
interface ProgressParams<T> {
  /**
   * The progress token provided in the request.
   */
  token: ProgressToken;

  /**
   * The progress value.
   */
  value: T;
}
```

## Cancellation

### Cancel Request

_Notification_:
- method: `$/cancelRequest`
- params: `CancelParams`

```typescript
interface CancelParams {
  /**
   * The request ID to cancel.
   */
  id: integer | string;
}
```

A cancelled request still returns a response, but may return partial results or an error with code `RequestCancelled` (-32800).

## Example Flow

### 1. Initialize

```json
// Client → Server
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "aide/initialize",
  "params": {
    "projectRoot": "file:///home/user/myproject",
    "clientInfo": { "name": "vscode-aidep", "version": "0.1.0" },
    "capabilities": { "streaming": true }
  }
}

// Server → Client
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "sessionId": "sess_abc123",
    "serverInfo": { "name": "aidep-opencode", "version": "0.1.0" },
    "capabilities": { "implementFunction": true }
  }
}

// Client → Server
{
  "jsonrpc": "2.0",
  "method": "aide/initialized",
  "params": {}
}
```

### 2. Implement Function (with streaming)

```json
// Client → Server
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "aide/implementFunction",
  "params": {
    "location": {
      "textDocument": { "uri": "file:///home/user/myproject/src/utils.ts" },
      "position": { "line": 42, "character": 0 }
    },
    "prompt": "Parse a CSV string into an array of objects using the first row as headers",
    "signature": "function parseCSV(input: string): Record<string, string>[]",
    "partialResultToken": "token-xyz"
  }
}

// Server → Client (streaming chunks)
{
  "jsonrpc": "2.0",
  "method": "$/progress",
  "params": {
    "token": "token-xyz",
    "value": { "chunk": "function parseCSV(input: string): Record<string, string>[] {\n" }
  }
}

{
  "jsonrpc": "2.0",
  "method": "$/progress",
  "params": {
    "token": "token-xyz",
    "value": { "chunk": "  const lines = input.trim().split('\\n');\n" }
  }
}

// ... more chunks ...

{
  "jsonrpc": "2.0",
  "method": "$/progress",
  "params": {
    "token": "token-xyz",
    "value": { "done": true }
  }
}

// Server → Client (final response)
{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "content": {
      "text": "function parseCSV(input: string): Record<string, string>[] {\n  const lines = input.trim().split('\\n');\n  const headers = lines[0].split(',');\n  return lines.slice(1).map(line => {\n    const values = line.split(',');\n    return headers.reduce((obj, header, i) => {\n      obj[header.trim()] = values[i]?.trim() ?? '';\n      return obj;\n    }, {} as Record<string, string>);\n  });\n}",
      "languageId": "typescript"
    }
  }
}
```

## Future Capabilities (not specified)

The following capabilities are planned for future versions:

- `aide/explain` - Explain code at a location
- `aide/refactor` - Refactor code with a given intent
- `aide/review` - Review a diff or code range
- `aide/complete` - Context-aware completion
- `aide/test` - Generate tests for a function

---

## Design Principles

1. **Human in control**: The server never modifies files directly. All changes are proposed to the client.

2. **Explicit actions**: Each capability is a discrete, well-defined action. No autonomous planning or multi-step execution.

3. **IDE agnostic**: The protocol makes no assumptions about the client implementation.

4. **Agent agnostic**: The server can wrap any AI backend (opencode, Claude Code, aider, local LLMs, etc.).

5. **Streaming first**: Long generations stream by default to provide responsive feedback.
